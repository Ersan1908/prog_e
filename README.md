# REST API фильмотеки - вариант 5

Лабораторная работа по дисциплине «Программная инженерия», МТУСИ.
Выполнил: **Новосельцев Алексей Сергеевич, БСТ-2556**.

FastAPI + SQLAlchemy 2 + SQLite. Реализованы 8 операций API, CRUD фильмов,
поиск по названию, фильтрация по году, жанру и рейтингу, сортировка,
пагинация, статистика, валидация и документация Swagger UI / ReDoc.

## Быстрый запуск

Нужен **Python 3.12+**. Команды выполняются из папки проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m app.seed
python -m uvicorn app.main:app --reload
```

В Windows окружение активируется командой `.venv\Scripts\activate`.
Если команда `python3` отсутствует, используйте `python` нужной версии.

- Swagger UI: <http://127.0.0.1:8000/docs>
- ReDoc: <http://127.0.0.1:8000/redoc>
- OpenAPI JSON: <http://127.0.0.1:8000/openapi.json>
- Проверка БД и API: <http://127.0.0.1:8000/health>

SQLite создаётся автоматически в `data/movies.db`, данные сохраняются после
перезапуска. `app.seed` добавляет 8 **вымышленных учебных** фильмов только в
пустую базу; повторный запуск не добавляет копии. Без seed база остаётся пустой.
Адрес БД можно изменить через `DATABASE_URL=sqlite:///путь/к/файлу.db`.
В Git файл рабочей базы не включается; данные воспроизводятся из JSON.

## Эндпоинты

| Метод | Путь | Назначение | Успех |
|---|---|---|---|
| GET | `/health` | Проверка API и БД | 200 |
| GET | `/api/v1/movies` | Список, поиск, фильтрация, сортировка, страницы | 200 |
| POST | `/api/v1/movies` | Добавление фильма | 201 |
| GET | `/api/v1/movies/{movie_id}` | Получение одного фильма | 200 |
| PUT | `/api/v1/movies/{movie_id}` | Полная замена полей фильма | 200 |
| DELETE | `/api/v1/movies/{movie_id}` | Удаление без тела ответа | 204 |
| GET | `/api/v1/movies/stats` | Количество, средний рейтинг, годы и группы жанров | 200 |
| GET | `/api/v1/genres` | Используемые жанры | 200 |

Редирект `/` на `/docs` и маршруты документации не включены в число восьми операций.
`stats` всегда считает всю базу, независимо от фильтров списка.

## Пример создания

```bash
curl -i -X POST http://127.0.0.1:8000/api/v1/movies \
  -H 'Content-Type: application/json' \
  -d '{"title":"Контрольный фильм","director":"Иван Петров","year":2024,"genre":"Драма","rating":8.2,"duration_minutes":110,"description":null}'
```

Ответ: `201 Created`, заголовок `Location: /api/v1/movies/ID` и JSON фильма с `id`.
Примеры всех методов находятся в `examples/requests.http` (VS Code REST Client
или аналогичный клиент). Подставьте фактический ID при чтении, замене и удалении.

## Поиск, фильтры и страницы

```bash
curl --get 'http://127.0.0.1:8000/api/v1/movies' \
  --data-urlencode 'q=ОРБИТА' \
  --data-urlencode 'year=2024' \
  --data-urlencode 'rating_min=8' \
  --data-urlencode 'sort_by=rating' \
  --data-urlencode 'order=desc' \
  --data-urlencode 'page_size=2'
```

| Параметр | Значение |
|---|---|
| `q` | Часть названия, 1-200 символов; регистр не учитывается, включая кириллицу |
| `year` | Точный год, 1888-2100 |
| `genre` | Точное совпадение жанра без учёта регистра |
| `rating_min`, `rating_max` | Включительный диапазон 0-10; минимум не больше максимума |
| `sort_by` | `id`, `title`, `year`, `rating`; по умолчанию `id` |
| `order` | `asc` или `desc`; по умолчанию `asc` |
| `page` | 1-1 000 000 000; по умолчанию 1 |
| `page_size` | 1-100; по умолчанию 10 |

Все фильтры объединяются условием AND. `%` и `_` в поиске - обычные символы.
При равенстве значений сортировки используется `id` по возрастанию.
Для пустой выборки `total_pages=0`; страница за пределами выдачи возвращает
`items=[]` с сохранением реального `total`. Поиск подстроки выполняется по всей
таблице, что подходит для объёма учебной фильмотеки.

## Валидация и ошибки

- `title`: непустая строка до 200 символов; `director`: до 120; `genre`: до 60.
- Пробелы по краям удаляются. Жанр нормализуется: ` дРАМА ` → `Драма`.
- `year`: целое 1888-2100; `duration_minutes`: целое 1-1000; `rating`: число 0-10.
- `description`: строка до 3000 символов или `null`; по умолчанию `null`.
- Числа в JSON должны иметь числовой тип; булевы значения не принимаются как числа.
- Неизвестные поля тела и query-параметры отклоняются.
- Невалидные данные: **422**; отсутствующий фильм: **404**.
- `PUT` требует все обязательные поля. Пропущенное `description` сбрасывается в `null`.

Защиту диапазонов дополняют `CHECK`-ограничения SQLite. SQLAlchemy передаёт
значения параметрами; поля сортировки выбираются из белого списка.
Авторизация не реализована: дополнительное требование выполнено сортировкой
и пагинацией. Проект предназначен для локальной учебной демонстрации.

## Проверки

```bash
python -m pip install -r requirements-dev.txt
ruff check .
ruff format --check .
python -m pytest --cov=app --cov-report=term-missing
```

В комплекте 66 тестов: CRUD, ошибки, границы, Unicode-поиск, буквальные `%` и `_`,
сочетание фильтров, сортировка, страницы, агрегаты, сохранение после перезапуска,
ограничения БД, повторное заполнение и схема OpenAPI. Каждый тест использует
отдельную временную SQLite; рабочая база не изменяется. В проверенном окружении
Python 3.12.14 все 66 тестов прошли; покрытие кода приложения без `app.seed` - 99%.
В Starlette 1.9.0 выводится предупреждение об устаревании HTTPX в TestClient;
оно не влияет на результат проверок.

GitHub Actions запускает те же проверки на Python 3.12 при push и pull request.
